# התקנת JobHunter במחשב אישי — צעד אחר צעד

המדריך מיועד למי שמתקין את JobHunter בפעם הראשונה על מחשב Windows, בלי רקע בפיתוח. ההתקנה לוקחת בערך 30–60 דקות, רובן המתנה להורדות.

- כל פקודה מופיעה בתיבה אפורה. יש להעתיק אותה כמו שהיא, להדביק בחלון PowerShell וללחוץ Enter.
- אחרי כל פקודה מתואר מה אמור להופיע. אם מופיע משהו אחר, יש לעבור ל[פתרון תקלות](#8-פתרון-תקלות).
- אפשר להיעזר בעוזר AI לאורך ההתקנה: [AI-HELP-PROMPT.md](AI-HELP-PROMPT.md).
- המדריך המלא, עם כל המסכים וההגדרות: [GUIDE.md](GUIDE.md).

**איך פותחים PowerShell:** לוחצים על כפתור Start, מקלידים `PowerShell` ולוחצים Enter. נפתח חלון כחול או שחור עם שורה שמתחילה ב-`PS C:\Users\...>`.

---

## 1. מה צריך לפני שמתחילים

1. **Windows 10 או 11** וחיבור לאינטרנט.
2. **Node.js** (גרסת LTS, 22.13 ומעלה): להוריד מ-https://nodejs.org ולהתקין עם ברירות המחדל. אחרי ההתקנה יש **לסגור ולפתוח מחדש** את PowerShell, ולבדוק:
   ```powershell
   node --version
   ```
   אמור להופיע מספר גרסה, למשל `v22.14.0` או `v24.1.0`.
3. **Git** (רק לדרך א' בשלב 3): להוריד מ-https://git-scm.com/download/win ולהתקין עם ברירות המחדל. בדיקה:
   ```powershell
   git --version
   ```
   אמור להופיע `git version 2...`.
4. **מודל שפה**, אחד מהשניים (ההסבר בשלב 2):
   - **Ollama**, מקומי וחינמי: https://ollama.com/download. דורש כרטיס מסך NVIDIA עם 8GB זיכרון לפחות;
   - **מפתח API** בתשלום, מאחד הספקים:
     - Anthropic (Claude): https://console.anthropic.com/settings/keys
     - OpenAI: https://platform.openai.com/api-keys
     - Google Gemini: https://aistudio.google.com/app/apikey
5. **חשבון בדרושים** (https://www.drushim.co.il), עם קורות החיים מועלים אליו.
6. **קורות החיים כקובץ PDF**, בעברית, באנגלית או בשתיהן. בשלב 4 יש טיפים איך להכין אותם.

## 2. מודל מקומי או API?

המודל קורא מודעות דרושים, מדרג אותן ומנסח טיוטות תשובה. הבחירה נעשית באשף, ואפשר לשנות אותה בכל רגע במסך Settings.

**בדיקת כרטיס המסך:**
```powershell
nvidia-smi
```
- מופיעה טבלה עם שם הכרטיס וזיכרון כמו `0MiB / 12288MiB`: המספר הימני הוא זיכרון הכרטיס (12288MiB = 12GB).
- מופיעה שגיאה כמו `nvidia-smi is not recognized`: אין כרטיס NVIDIA, ולכן מתאים ספק API.

| | Ollama (מקומי) | ספק API |
|---|---|---|
| **מתאים כש...** | יש כרטיס NVIDIA עם 8GB ומעלה | המחשב חלש, אין כרטיס מתאים, או רוצים איכות כתיבה גבוהה יותר |
| **עלות** | חינם | תשלום לפי שימוש, לפי מחירון הספק |
| **פרטיות** | שום דבר לא יוצא מהמחשב | תיאורי המשרות, פרטי הפרופיל וקורות החיים נשלחים לשרתי הספק |
| **מהירות** | תלויה בכרטיס. דירוג של עשרות משרות לוקח דקות | בדרך כלל מהיר |

**עם Ollama:**
1. להתקין את Ollama ולפתוח את האפליקציה. סמל הלאמה מופיע ליד השעון.
2. להוריד את המודל (בערך 8GB, פעם אחת):
   ```powershell
   ollama pull gemma4:12b
   ```
   בסוף מופיע `success`. אם מדלגים על השלב הזה, `npm start` יציע להוריד את המודל בעצמו.

**עם ספק API:**
1. לפתוח חשבון אצל הספק, להוסיף אמצעי תשלום או קרדיט, וליצור מפתח (API key) בקישור שבשלב 1. המפתח מוצג פעם אחת בלבד, ולכן כדאי להעתיק אותו מיד.
2. המפתח נשמר **רק** בקובץ `.env` במחשב, ולעולם לא נשלח לשום מקום חוץ מהספק עצמו. אסור לשלוח את הקובץ הזה לאף אחד.
3. כדי לשלוט בעלות: במסך Settings אפשר להזין את מחירי הספק ולראות כמה הוצאתם, ולהגדיר `Daily token limit`, מגבלה יומית שאחריה המערכת עוצרת את השימוש במודל עד מחר.

## 3. הורדת הקוד

יש שתי דרכים. דרך א' נוחה יותר לעדכונים.

### דרך א': git clone (בתור collaborator)
1. בעל הפרויקט מוסיף אתכם ב-GitHub (Settings → Collaborators). מגיע מייל הזמנה, ויש ללחוץ בו **Accept invitation**. צריך חשבון GitHub.
2. ב-PowerShell:
   ```powershell
   cd $HOME\Documents
   git clone https://github.com/Orel009/JobHunterAI.git
   cd JobHunterAI
   ```
   בפעם הראשונה ייפתח חלון התחברות ל-GitHub, ויש להתחבר עם החשבון שקיבל את ההזמנה. בסוף מופיע `Receiving objects: 100%`.
3. **עדכון לגרסה חדשה בעתיד:**
   ```powershell
   cd $HOME\Documents\JobHunterAI
   git pull
   npm start
   ```

### דרך ב': קובץ ZIP
1. בעל הפרויקט מריץ `npm run package` ושולח את הקובץ `JobHunter-<גרסה>.zip`. הקובץ לא מכיל שום מידע אישי.
2. לשמור את הקובץ, ללחוץ עליו בכפתור הימני ← **Extract All**, ולחלץ לתיקיית Documents.
3. ב-PowerShell (בהתאם למספר הגרסה בשם הקובץ):
   ```powershell
   cd $HOME\Documents\JobHunter-0.3.0
   ```
4. **עדכון לגרסה חדשה בעתיד:** לחלץ את ה-ZIP החדש לתיקייה חדשה, ולהעתיק אליה מהתיקייה הישנה את התיקייה `data` ואת הקובץ `.env`. שם נמצאים כל הנתונים וההגדרות. אחרי זה מריצים `npm start` בתיקייה החדשה.

## 4. הפעלה ראשונה ואשף ההגדרה

1. מתוך תיקיית הפרויקט:
   ```powershell
   npm start
   ```
   (אפשר גם ללחוץ לחיצה כפולה על `start.cmd` בתיקייה.)
2. **מה אמור להופיע:** שורות עם `✓` בירוק. בפעם הראשונה ההתקנה לוקחת כמה דקות: `npm install` ואחריו `npx playwright install chromium`, הדפדפן שהמערכת משתמשת בו.
   - שורות שמתחילות ב-`npm warn` (למשל `deprecated` או `allow-scripts`) תקינות, ואין צורך לעשות איתן כלום.
   - שורות עם `!` בצהוב הן אזהרות, ובהפעלה הראשונה הן תקינות, למשל `No profile yet — the setup wizard opens in the dashboard`.
   - שורה עם `✗` באדום עוצרת את ההפעלה. ההודעה מסבירה מה לתקן.
3. בסוף מופיעה מסגרת עם `DRY RUN — nothing is sent`, והדפדפן נפתח בכתובת http://127.0.0.1:8787 עם **Setup — step 1 of 9**.
4. **אסור לסגור את חלון PowerShell.** הוא המערכת עצמה. לעצירה: `Ctrl+C`.

### שלבי האשף

כפתור **Next →** ממשיך. כשהוא אפור, יש קודם ללחוץ **Save**. אפשר לחזור אחורה בכל שלב.

**1. About you**
- השם המלא בדיוק כמו בקורות החיים.
- **לשון נקבה / לשון זכר:** קובע איך ייכתב כל טקסט עברי בשמכם, כמו טיוטות תשובה ושאלות קבועות.

**2. Language model**
- **Ollama:** לבחור `ollama` ולכתוב `gemma4:12b` בשדה המודל.
- **ספק API:** לבחור את הספק, להדביק את המפתח בשדה המפתח וללחוץ **Save**. אחרי זה לבחור מודל מהרשימה שמופיעה בשדה.
- ללחוץ **Test connection**. אמור להופיע `✓ works`.

**3. Your CV**
- להעלות PDF בעברית, באנגלית או בשתיהן, ולחכות להודעה `Your CV has been read`. עם Ollama זה יכול לקחת כמה דקות.
- **מה עושה קובץ טוב:**
  - PDF שנשמר מ-Word או מ-Google Docs, לא סריקה או צילום. בדיקה פשוטה: אם אפשר לסמן את הטקסט בקובץ עם העכבר, הוא תקין.
  - בלי סיסמה, ועד 4MB (זו גם המגבלה של דרושים).
  - לכל תפקיד: שם החברה, התפקיד, ותאריכי התחלה וסיום, עדיף עם חודש (`03/2022 – 08/2024`). מזה מחושבות שנות הניסיון.
  - רשימת כישורים מסודרת.
- המערכת שומרת רק פרטים שמופיעים בקורות החיים, ולא ממציאה כלום.

**4. Review your profile**
- לבדוק את הטלפון, המייל, העיר, התפקידים והתאריכים, ולתקן מה שצריך.
- **סוג התפקיד** חשוב: `work` (עבודה בתשלום), `project`, `education`, `military` ועוד. שנות ניסיון בכישור נספרות **רק** מתפקידי `work`.
- ללחוץ **Save**.

**5. Skills — קישור כישורים לתפקידים**
- בעמודה **Used in roles** יש לסמן, לכל כישור, את התפקידים שבהם באמת השתמשתם בו. לדוגמה: אם עבדתם עם React בתפקיד האחרון בלבד, מסמנים רק אותו.
- כשטופס שואל "כמה שנות ניסיון יש לך ב-React?", התשובה מחושבת מהתאריכים של התפקידים המסומנים.
- **Level:**
  - `strong` — כישור שאפשר לדבר עליו בביטחון בראיון;
  - `basic` — היכרות בלבד. נספר בהתאמה למשרות, אבל לעולם לא עונה אוטומטית "כן" על שאלת ניסיון.
- **delete** — למחוק כישורים שלא רוצים להציג. כישור שנמחק לא יחזור גם בעדכון קורות חיים.
- ללחוץ **Save**.

**6. Experience — הצהרת ניסיון**
- אופציונלי. המספר הכולל של שנות הניסיון המקצועי בפיתוח, ושורת **Basis** שמסבירה על מה הוא מבוסס (למשל "Acme 2022–2024 + Globex 2024–היום").
- ההצהרה משמשת רק לשאלות **כלליות**, כמו "האם יש לך 2 שנות ניסיון בפיתוח?". היא לא משמשת לשאלות על טכנולוגיה מסוימת.
- **חשוב:** כל טענה כאן ובכל מקום אחר בפרופיל חייבת להתאים לקורות החיים, וצריך להיות אפשר להגן עליה בראיון. המערכת תענה בשמכם על סמך מה שכתוב כאן. אם יש ספק, עדיף מספר נמוך יותר או להשאיר ריק.

**7. What to search**
- **Role types:** סוגי התפקידים לחיפוש. אפשר להפעיל, לכבות ולשנות עדיפות (tier 1 = הכי רלוונטי).
- **Locations:** ערים או אזורים, אחד בכל שורה (למשל `חיפה`, `השרון`). ריק = כל הארץ.
- **Max required years:** משרות שדורשות יותר שנות ניסיון מזה ידולגו.
- ללחוץ **Save**.

**8. Drushim**
1. בדרושים, באזור האישי ← קורות חיים, להעלות את קובצי קורות החיים.
2. לכתוב ב-**Hebrew CV name** / **English CV name** את השמות **בדיוק** כמו שדרושים מציג אותם, כולל `.pdf` אם הוא מופיע. ההגשה שולחת את הקובץ ששמור בדרושים, לא את הקובץ מהמחשב. ללחוץ **Save**.
3. ללחוץ **Open the Drushim login window**. נפתח חלון דפדפן, ובו מתחברים לדרושים **ידנית**. המערכת אף פעם לא מקלידה סיסמה. אחרי ההתחברות סוגרים את החלון, והסטטוס משתנה ל-`logged in`.

**9. Standard answers**
- תשובות לשאלות שחוזרות בכל טופס, כמו עיר, משרה מלאה וזמינות. לענות רק מה שנכון. שדה ריק = המערכת תשאל בכל פעם.
- ללחוץ **Finish setup**. נפתח ה-dashboard, ובפס העליון כתוב `DRY RUN` בצהוב.

## 5. ריצה ראשונה בטוחה (DRY_RUN=true)

ברירת המחדל היא `DRY_RUN=true`: המערכת ממלאת טפסים ומצלמת, אבל **לא שולחת כלום**. כדאי לעבוד ככה כמה ימים, עד שסומכים על התשובות.

1. ללחוץ **Discover Drushim**. המערכת מחפשת, מסננת ומדרגת. עם Ollama זה יכול לקחת 10–20 דקות. ההתקדמות מוצגת ב-**Live log** בתחתית.
2. במסך **Jobs** המשרות ממוינות לפי `Rank`. לחיצה על שורה מציגה את הסבר הציון.
3. ללחוץ **apply** על משרה מתאימה. המערכת פותחת את טופס ההגשה, ממלאת מה שידוע ועוצרת.
4. במסך **Review queue** עוברים על כל שדה ועל המקור שלו (`profile`, `answers bank`, `LLM draft`…), עונים על שאלות פתוחות ומתקנים טיוטות.
5. ללחוץ **Approve → DRY RUN (no submit)**. הסטטוס הופך ל-`dry_run_ok`, ויש צילום מסך של הטופס המלא. **שום דבר לא נשלח.**

**שאלות סינון:** בדרושים יש הצהרות שצריך לסמן ב-✓, למשל "יש לי ניסיון בפריוריטי". **אסור לסמן הצהרה שאינה נכונה.** אם התשובה האמיתית היא "לא", עונים "לא", והמערכת מדלגת על המשרה (`skipped_screening`). זה בסדר: עדיף לדלג מאשר להגיש עם הצהרה שקרית.

## 6. מעבר לשליחה אמיתית

רק אחרי שכמה הגשות ניסיון נראו נכונות:
1. בחלון PowerShell ללחוץ `Ctrl+C` כדי לעצור.
2. לפתוח את קובץ ההגדרות:
   ```powershell
   notepad .env
   ```
3. לשנות את השורה `DRY_RUN=true` ל-`DRY_RUN=false`, לשמור (`Ctrl+S`) ולסגור.
4. להפעיל מחדש:
   ```powershell
   npm start
   ```
   בפס העליון יופיע `LIVE` באדום. כפתור האישור הופך ל-**Approve → SUBMIT for real**, עם חלון אישור נוסף.
5. גם עכשיו אין שליחה בלי אישור ידני לכל הגשה, והמכסה היומית (`Daily apply limit` במסך Preferences) נאכפת.
6. חזרה למצב ניסוי: `DRY_RUN=true` והפעלה מחדש.

## 7. שימוש יומי

1. להפעיל עם `npm start` או בלחיצה כפולה על `start.cmd`.
2. ללחוץ **Discover Drushim**, או להריץ מראש ציד מלא שמחפש, מדרג ומכין תוכניות, בלי לשלוח:
   ```powershell
   npm start -- --hunt
   ```
3. ב-**Review queue** לעבור על ההגשות שהוכנו, ולאשר או לדחות.
4. ב-**Answers bank** לענות על שאלות ממתינות. כל שאלה נענית פעם אחת, והתשובה משמשת בכל המשרות הבאות.
5. **קורות חיים חדשים:** להעלות אותם במסך **Profile**, לאשר את השינויים, ולהעלות את אותו קובץ **גם לדרושים**.
6. בסיום: `Ctrl+C`.
7. **גיבוי:** מדי פעם לעצור את המערכת ולהעתיק את התיקייה `data` למקום בטוח.

## 8. פתרון תקלות

הצעד הראשון תמיד הוא הפקודה שבודקת הכל ומסבירה מה לתקן, בלי לשנות כלום:
```powershell
npm run doctor
```

| # | מה מופיע | מה עושים |
|---|---|---|
| 1 | `node` או `npm` `is not recognized` | Node לא מותקן, או ש-PowerShell נפתח לפני ההתקנה. לסגור ולפתוח מחדש את PowerShell. אם זה לא עוזר, להתקין שוב את Node מ-https://nodejs.org |
| 2 | `running scripts is disabled on this system` | מגבלה של PowerShell. להריץ פעם אחת `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, לענות `Y`, ולנסות שוב. אפשר גם להשתמש ב-`start.cmd` |
| 3 | `git` `is not recognized`, או `Repository not found` | Git לא מותקן (שלב 1), או שההזמנה ב-GitHub לא אושרה, או שההתחברות הייתה לחשבון אחר. אפשר תמיד לעבור לדרך ב' (ZIP) |
| 4 | `Ollama is not reachable` או `Model gemma4:12b is not installed` | לפתוח את אפליקציית Ollama ולהריץ `ollama pull gemma4:12b` |
| 5 | `does not fit the GPU`, או שהדירוג איטי מאוד | הכרטיס חלש מדי למודל. במסך Settings לבחור ספק API |
| 6 | `No API key` / `Cannot reach …` / `Test connection` נכשל | במסך Settings להדביק שוב את המפתח, בלי רווחים, וללחוץ **Save** לפני **Test connection**. לבדוק שיש קרדיט בחשבון אצל הספק |
| 7 | קריאת קורות החיים נכשלת או לא מוצאת כלום | ה-PDF כנראה סרוק או מוגן בסיסמה. לשמור אותו מחדש מ-Word או מ-Google Docs (File → Download → PDF) ולהעלות שוב |
| 8 | `Drushim: NOT logged in`, או `CV "…" not found in the panel` | ללחוץ **Open the login window** בבאנר ולהתחבר. אם הבעיה היא בקורות החיים: השם במסך Preferences חייב להיות זהה בדיוק לשם בדרושים. השמות הקיימים מופיעים בהערה ℹ בכרטיס ההגשה |
